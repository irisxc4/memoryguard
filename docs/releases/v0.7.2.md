# MemoryGuard v0.7.2

Date: 2026-08-16

Status: targeted compatibility and correctness release

## Fixed

- Trusted Agent/project scope is preserved across memory writes and read-back,
  so a successful write remains readable under its intended scope without
  weakening scope isolation.
- Codex Hook lifecycle handling uses verified thread/workspace evidence,
  preserves resumable ordinary `Stop` boundaries, and conservatively reconciles
  terminal or deleted threads. The Codex transport repair normalizes the active
  Python interpreter and UTF-8 stdio and performs live `initialize`,
  `tools/list`, `memory_status`, and `memory_read` checks.
- The Codex transport repair script and its tests use
  `memoryguard.toml_compat`, preserving the `tomllib.loads` and
  `tomllib.TOMLDecodeError` call interface on Python 3.10 and 3.12.

## Verification evidence

- The reported Python 3.10 collection failure was caused by direct `tomllib`
  imports in the repair script and its test; both imports now use the project
  compatibility module.
- The reported Python 3.12 failure was a stale public-version assertion; it now
  expects `0.7.2`, matching the package version.
- Targeted verification command:
  `python -m pytest tests/test_repair_codex_memoryguard_transport.py tests/test_v2_public_upgrade.py -q`
- Repository whitespace verification: `git diff --check`.

This note records only the focused changes and verification requested for the
v0.7.2 correction; it does not claim a full-suite result.
