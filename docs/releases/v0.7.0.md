# MemoryGuard v0.7.0

Status: **local release acceptance passed; ready for commit/publish, not yet published**
Date: 2026-08-12

v0.7.0 is the V2-only release line. This note defines the implementation
boundary, migration contract, recorded evidence, and gates required before a
tag or package publication. It is not a declaration that the current full
repository is green.

## V2-only boundary

The production runtime is physically V2-only:

- V1 runtime/store modules are removed from the production entrypoint import
  closure. `V1_ACTIVE` is a migration starting state, not a runnable fallback.
- Legacy-format readers are confined to `memoryguard.migration`. Public MCP,
  CLI, Hook, Provider, GUI, `cutover_v2`, and `runtime_v2` entrypoints do not
  import or dispatch the retired V1 runtime. Non-V2, unknown, or corrupt state
  fails closed with `v2_upgrade_required` or an equivalent stable error.
- V1 data, frozen sources, migration backups, and their receipts remain local
  rollback/audit evidence. They are not V2 runtime write targets and are not
  removed as part of this release.

The six named V2 control planes are:

| Plane | Boundary |
| --- | --- |
| Memory | Governed V2 atoms, revisions, visibility, deduplication, supersede chains |
| Evidence | Decision/evidence receipts, source links, outbox, audit and undo data |
| History | Separate raw conversation evidence; explicit read/export only |
| Source | Authorized files/folders, bounded inventory, source objects and coverage |
| Binding | Trusted Agent identity, provider binding, source selection and drift |
| Group | Personal/shared membership, same-group governance scope and lifecycle |

## Governance and canonical state

Canonical reconciliation builds durable V2 rule bundles:

- `shared_baseline` for group-wide obligations;
- `agent_overlay` for provider/Agent-specific obligations;
- `project_overlay` for project-scoped obligations.

Every folded source keeps a source link to its canonical definition. The
recoverable saga verifies parity, drains required outbox work, activates the
canonical read path, and only then shadows old duplicates. A failed phase stays
retryable; old sources are recoverable rather than silently deleted.

V2 automatic organization performs exact and semantic duplicate detection
inside one explicit `share_group_id`. Its outcomes are explicit:
`deduplicated`, `superseded`, `conflicted`, or `quarantined`. Agent identity is
retained in provenance. Rule duplicate scans use bounded three-layer matching
and produce governed merge proposals; automatic merge conditions and human
approval/capability gates are recorded. Merge, supersede, conflict, quarantine,
and undo operations preserve evidence, audience/scope, idempotency, and
decision receipts. A different Group cannot enter the candidate set or mutate
the same governance namespace.

## Product surfaces

### Knowledge files and folders

A selected folder becomes a governed book; selected files become governed
documents. Source files remain in place. The Content Plane is the only owner of
source bodies; Knowledge stores metadata, references, chunks, and indexes.
Re-ingest, remove, restore, purge, and candidate review are V2 operations. A
knowledge candidate does not become long-term Memory without explicit governed
acceptance.

### GUI Agent and Group management

The native GUI exposes Agent discovery with names/instances, source selection,
Binding status and drift, personal/shared Group membership, and member
operations including bind, unbind, leave, and dissolve. Membership changes use
transactional system receipts and outbox events. Group previews retain member
identity and bounded status rather than exposing unrelated tenant data.

Projection, Knowledge, import, History, maintenance, release, and compatibility
requests use durable V2 `TaskRun` records. Status survives GUI reload and
process restart. Cancellation is cooperative and bounded; owned background
workers/processes and cleanup callbacks must be joined or completed before
shutdown. A cancelled or failed task must not be reported as successful and
must not leave an owned worker behind.

### CodeGraph and Graphify

Graphify integration accepts a trusted metadata export, not raw `graph.json` or
source bodies. CodeGraph persists:

- trusted scope and source role;
- provenance and source maps;
- immutable revisions and source tombstones;
- projection outbox/checkpoints; and
- bounded `query`, `path`, `explain`, and `affected` operations with
  production/test/fixture provenance filters.

The embedded GUI extraction path can represent the production chain
`control → handler → API method → GuiOperationSpec → native handler`. Raw
source text, snippets, credentials, authority, ACLs, and arbitrary Graphify
IDs are rejected at the adapter boundary.

## Security, audit, and rollback

V2 operations fail closed on unavailable/corrupt manifest state, missing trusted
scope, invalid provenance, unsafe metadata, symlink/reparse paths, stale
generation, and idempotency conflicts. Public errors use stable codes and
redacted diagnostics; public receipts do not expose source bodies or unbound
filesystem paths. Scope isolation is checked at the trusted transport boundary,
not inferred from browser or payload fields.

Governance decisions, source links, outbox events, holds, and digests form the
audit trail. Release rollback stores the previous target as a Content Plane blob
and occurrence under a hold, then restores it through a scoped release receipt.
Rollback does not trust an arbitrary backup path, and failed partial operations
must compensate or remain visibly blocked.

## Upgrade from v0.6.2

Upgrade the package first. If the old installation uses a separate user data
home, pass the same `--data-home` value on every command below.

```bash
python -m pip install --upgrade agent-memguard
memoryguard --version

# Read-only preview. Required: status=PREVIEW, writes_performed=false.
memoryguard upgrade --workspace .

# Explicit migration. Required: status=V2_READY, activation_required=true.
memoryguard upgrade --workspace . --apply

# Explicit activation. Required: exact confirmation and fresh drift check.
memoryguard upgrade --workspace . --apply --confirm V2_ACTIVE
memoryguard doctor
```

The apply path reads old input only through `memoryguard.migration`, builds the
V2 shadow, migrates Agent/Group control records, validates frozen and live
sources, and stops at `V2_READY`. Activation is a separate exact-confirmation
step. A failed control or validator stage remains non-active; there is no
silent fallback. Keep V1 data, migration backups, evidence, and receipts until
the release gate authorizes cleanup. Re-running an active upgrade is
idempotent.

## Release gate

v0.7.0 may be tagged and published only when every item below has a passing,
reviewable receipt:

1. `pyproject.toml`, `memoryguard.__version__`, CLI metadata, wheel metadata,
   README, Changelog, and release note all agree on `0.7.0`; `git diff --check`
   is clean.
2. V1 retirement AST and clean-subprocess import gates pass for all production
   entrypoints; only `memoryguard.migration` reads legacy input; no V1 runtime
   fallback or compatibility import remains in the production closure.
3. Canonical reconciliation reaches ready state with source-link/parity/outbox
   evidence; same-group cross-Agent governance passes; cross-Group isolation,
   deduplication, merge, supersede, quarantine, audit, and undo receipts pass.
4. GUI Agent names/instances and Group member management pass; Knowledge
   file/folder operations pass; TaskRun status, cancellation, recovery, and
   zero-owned-worker/process shutdown pass.
5. CodeGraph/Graphify metadata-only, provenance, source-map, revision,
   tombstone, outbox, production-filter, query/path/explain/affected, and
   source-body rejection checks pass.
6. The same Graphify changes are applied to a complete upstream source
   checkout, its tests pass, and its package/install verification passes. The
   current `H:/ai/workspace/graphify` sparse overlay is not sufficient; do not
   substitute installed `site-packages/graphify`.
7. Supported-matrix CI, package smoke, security fail-closed/isolation/audit,
   rollback/hold, and the complete 0.6.2 upgrade rehearsal pass. No unresolved
   blocker remains and main acceptance is explicitly closed.

Until then: release status is **blocked**, migration backups and audit evidence
stay intact, and no `production_complete` claim is valid.
